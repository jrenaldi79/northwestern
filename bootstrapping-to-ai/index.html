LESSON 07 / HARNESS

Using Claude Code

The agentic coding environment we'll use for code-heavy projects.

Once Cowork feels natural, step up to Claude Code — a harness around Claude that can read and write files, run commands, and ship real software. It's our default when a task is mostly code. We'll use the desktop app — but when you start a project, pick the cloud environment and connect a GitHub repo. Do not select Local.

Why cloud, not local. When you open Claude Code from the desktop app it asks where you want to work. Choose Cloud and pick the GitHub repo you want Claude to work inside. Claude spins up a sandboxed container, mounts the repo, and the agent can only touch what's in there.

If you pick Local, Claude Code runs against your actual filesystem and terminal — it can read any file on your computer, run arbitrary commands, install software, and touch anything your user account can touch. Powerful, and genuinely risky for a first project. Start in the cloud environment. Graduate to local only once you understand the trade-offs.

LESSON 08 / BUILDING BLOCKS

Skills vs. Agents

The two primitives you'll compose into everything else.

Once you're comfortable in Cowork and Claude Code, the next question is: how do I teach the model to do something specific, and when should I hand the work to a separate worker? That's the Skills vs. Agents distinction. Skills are recipes — instructions Claude follows inside your conversation. Agents are colleagues — separate workers with their own context, tools, and permissions. Get fluent with both.

Skills vs. Agents — the cheat sheet
Skills Agents
What it is A folder (SKILL.md + optional scripts, references, assets) that teaches Claude how to do a specific task. A Markdown file with YAML frontmatter defining a specialized assistant with its own system prompt, tools, and permissions.
Mental model A recipe. Step-by-step instructions Claude follows in the main conversation. A colleague. A separate worker with a focused role who does the job and reports back.
Where it runs In the main conversation — everything stays in your chat. In its own separate context window — only a summary returns.
Context impact Adds to your context window (progressive disclosure helps). Preserves your context. Verbose output stays in the agent's window.
Best for Repeatable workflows: creating docs, generating frontend, onboarding flows, MCP orchestration. Long-running roles: code review, debugging, data analysis, parallel research — anything with lots of output or needing tool restrictions.
How it triggers Auto-matches on the skill's description field, or explicitly by asking for it. Auto-delegates based on the agent's description, or via @-mention / --agent flag.
Tool access Uses whatever tools the main conversation has (can restrict via allowed-tools). Independently configurable allowlist/denylist, own MCPs, own permission mode. Can be locked to read-only.
Model choice Uses the conversation's model. Configurable per agent — Haiku, Sonnet, Opus, or inherit.
Foreground / background Always foreground (in-conversation). Foreground (blocking) or background (concurrent). Ctrl+B to background.
Persistent memory No built-in memory between sessions. Optional: user, project, or local memory scope — agents accumulate knowledge.
Can nest? Skills can reference other files and scripts; agents can preload skills. Agents cannot spawn subagents. Chain from the main conversation, or use Agent Teams.
Where it lives Settings → Skills (claude.ai), or .claude/skills/ in Claude Code. .claude/agents/, ~/.claude/agents/, managed settings, or plugins.
Works in Claude.ai, Claude Code, and API — portable. Claude Code only (terminal, desktop, web sandbox).
Built-in examples docx, pptx, xlsx, pdf, frontend-design, skill-creator. Explore (read-only codebase search), Plan (plan-mode research), General-purpose.
The rule of thumb. For verbose, investigation-heavy work (long test runs, log analysis, large codebase exploration) delegate to an Agent to preserve your main context window. For repeatable, deterministic output (a PRD, a styled report, a formatted spreadsheet) reach for a Skill. The two compose — agents can preload skills to specialize further.

LESSON 10 / QUALITY

Evals

How you know your AI is actually working.

Evals are the discipline that separates a demo from a product. If you can't measure whether your system is getting better, you're not engineering — you're vibing.

Evals are to agents what performance reviews are to employees. — John Renaldi

You hire someone, you set expectations, you check in on how they're doing against those expectations, you coach them when they're off. Evals are the same feedback loop — just for a system that will run a million times instead of forty hours a week. These four resources give you the theory and the practice.

  • 01
    How to Build AI Evals in 2026 (Step-by-Step, No Hype) Aakash Gupta·YouTube A pragmatic walkthrough: use real production traces, do real error analysis, bring in LLM judges, and structure it all with the data-task-scores framework.
    Watch
  • 02
    If You Don't Understand AI Evals, Don't Build AI Aakash Gupta·YouTube The "why you can't skip this" companion video. Builds an eval from scratch against Linear's MCP server and talks through how teams sustain an eval culture past the first week.
    Watch
  • 03
    Demystifying evals for AI agents Anthropic Engineering·article How Anthropic thinks about designing evals across agent types — coding, conversational, research, computer use — including grading strategies, handling non-determinism, and building eval harnesses production teams can actually run.
    Read
